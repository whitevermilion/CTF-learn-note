```txt
HTTP Method is GET

Use CTF**B Method, I will give you flag.

Hint: If you got 「HTTP Method Not Allowed」 Error, you should request index.php.
```

## 翻译

1.  **`HTTP Method is GET`**
    - **翻译**：当前的 HTTP 方法是 GET。
    - **解析**：网站告诉你，现在默认的访问方式是 `GET` 请求。

2.  **`Use CTF**B Method, I will give you flag.`\*\*
    - **翻译**：使用 CTF\*\*B 方法，我就会给你 flag。
    - **解析**：这是题目的**核心要求**。它明确告诉你，需要使用一种名为 “CTF**B” 的 HTTP 方法去请求，才能得到 flag。这里的 `**`是通配符，代表你需要找出中间缺失的两个字母，例如`CTFHUB`、`CTF PUB` 或其他组合。

3.  **`Hint: If you got 「HTTP Method Not Allowed」 Error, you should request index.php.`**
    - **翻译**：提示：如果你遇到「HTTP 方法不被允许」的错误，你应该去请求 `index.php` 这个文件。
    - **解析**：这是一个重要的**路径提示**。如果你直接在根路径 `/` 上尝试新方法，服务器可能会返回 405 错误。此时，你需要将请求的目标路径改为 `/index.php`。

## 二次思考为什么。

前一个curl命令得到了响应而后者没有？这是不是意味着，curl命令必须指定对象？
你访问的两个路径（/ 和 /index.php）在服务器看来是完全不同的资源地址。服务器的程序（如Apache/Nginx + PHP）可以针对每个路径编写不同的处理逻辑。

    当你访问 /index.php 时：服务器明确地找到并执行了 index.php 这个脚本文件。该脚本的代码逻辑就是返回你看到的那段HTML提示。
    当你访问 /（根路径）时：服务器通常会尝试寻找一个默认的索引文件（如 index.php, index.html, default.htm 等）。根据服务器的配置，它可能有以下几种行为：
        内部重定向：将 / 请求，内部转发给 /index.php 来处理，然后返回结果（这时你两次请求看到的内容会一样）。
        返回一个不同的默认页（比如一个纯图片或空白页）。
        直接返回一个错误或空响应。

### 查看完整的HTTP响应头

要真正理解服务器在“做什么”，你必须查看完整的HTTP响应头。curl不加参数时，默认只输出响应体。空白的输出不代表服务器没响应，可能只是响应体为空。

```bash

red@Arch ~
❯ curl -I http://challenge-0fb646abb147d09f.sandbox.ctfhub.com:10800/
HTTP/1.1 302 Moved Temporarily
Server: openresty/1.21.4.2
Date: Wed, 04 Feb 2026 10:56:08 GMT
Content-Type: text/html; charset=UTF-8
Connection: keep-alive
X-Powered-By: PHP/5.6.40
Location: index.php
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: X-Requested-With
Access-Control-Allow-Methods: *

```

HTTP/1.1 302 Moved Temporarily
状态码：302 代表 “临时重定向”。这是最核心的信息。
含义：服务器明确告诉你：“你请求的资源（根路径 /）暂时不在这个地址了，我告诉你去另一个地方找。”

Location: index.php
重定向目标：这是 302 状态的配套指令。它告诉客户端（你的curl或浏览器）：“请自动跳转到 index.php 这个新地址。”
